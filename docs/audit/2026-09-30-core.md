## B. 明确的风险（未实跑）

1. **【高】明文 HTTP、token 进 URL、401 即清密钥三者叠加**：`api.rs:33-35` 地址不带协议时补 `http://`；`ws.rs:50` token 同时放在 `?token=`；`client/mod.rs:298-309`、`account.rs:113-118` 任一 401 就 `wipe_crypto`。链路上伪造一个 401 即可销毁全部加密状态。建议：release 只允许 https（本机/调试地址除外）；WS 只用头部带 token；401 先只清 token，加密状态留到重新登录时处理。
2. **【中】附件格式可被发送方降级**：`attachments.rs:56-61` v1 整文件进内存（上限 100MB）；`api.rs:173-192` 下载无大小上限、不比对 `wire.size`。建议 v1 限 25MB；下载按 `wire.size` 设上限。
3. **【中，Android】长中文文件名超过 255 字节**：`util.rs:79-90` 按字符截 80 个，再加 35 字节前缀；ext4/f2fs 上 ≥73 个汉字即失败。建议按 UTF-8 字节截到约 150 字节并保留扩展名。
4. **【中】附件上传途中本地删除，消息仍会发出**（`attachments.rs:121-152`）；没有取消发送接口。
5. **【中低】`verify_code` 半成功**（`account.rs:53-58`）：密钥上传成功后 `/v1/me` 失败，返回 Err 但登录态已写入。
6. **【中低】WS 循环里内联处理帧**（`sync.rs:307-321, 293, 521`）：长耗时处理会被空闲判断误判超时；`notify_waiters` 会丢。
7. **【设计】群成员表完全由服务端决定**；已核验联系人换钥后不阻断发送。
8. **【低】本地元数据与残留**：资料缓存、群成员、`seen` 表明文；未开 `secure_delete`；Content 无 padding。

## D. 功能缺口
- **P0**：解密失败后的补救（保留旧会话 + 按消息 id 重传请求）；日志出口（核心里只有 `tracing::warn!`，没有 subscriber 也没导出日志回调，线上无从排查）；release 强制 https、token 不进 URL。
- **P1**：附件进度回调与取消发送；重新登录保留同一设备身份（现在每次 `verify_code` 新建 Account，令牌过期就让所有联系人看到"安全码已变更"）；挂起群消息的超时占位与密钥重请求；加密备份与恢复；消息编辑；群消息按成员已读；通话跟踪持久化。
- **P2**：多设备；sealed sender 与 padding；群成员变更签名；断点续传；Olm 会话主动轮换；加密全文索引。
