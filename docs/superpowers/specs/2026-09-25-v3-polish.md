# Hush v3 收尾（遗留缺口 + 常用功能补齐）

日期：2026-09-25。延续 [设计文档](2026-09-24-hush-design.md) 与 [接口 v2](2026-09-24-api-v2.md)。本轮服务端无需改动（附件复用、@提及都在加密内容内完成）。所有本地库改动通过 `PRAGMA user_version` 迁移，不清数据。

## 1. 核心库（core/）——UniFFI 导出新增（两端需同步适配）

| 编号 | 内容 |
|---|---|
| K1 删除会话 | `delete_conversation(conv_id)`：删除该会话的全部本地消息、附件缓存文件与会话行（群会话不退群；群有新消息时重新出现），发 `ConversationsChanged`。 |
| K2 邮箱缓存 | 任何不带 `email` 的资料来源（邮箱搜索、群成员、朋友圈、profile_updated 事件）都不得清掉缓存中的 email；只有 `/v1/users/{id}`、`/v1/me`、`/v1/friends` 的结果与删好友可以改写它。 |
| K3 统一排序 | 本端发出的消息在服务端接受后，把 `sort_ts` 更新为服务端返回的 `server_ts`（并发 `MessageUpdated`），使双方消息顺序以服务端时间为准；发送中/失败的消息保持本地时间。迁移：已有已发送消息若有 server_ts 则回填。 |
| K4 转发 | `async forward_message(message_id, conv_ids: Vec<String>) -> Vec<MessageItem>`：把文字或附件消息作为新消息发到多个会话（附件复用已上传的密文 id 与密钥，不重新上传；引用、回应不转发）；单个目标失败不影响其他目标（失败的那条状态为 failed）。新消息 `MessageItem.forwarded: bool = true`（Content 新增可选字段 `forwarded`）。 |
| K5 草稿 | `set_draft(conv_id, text: Option<String>)`；`ConversationSummary.draft: Option<String>`；草稿字段级加密存储；发送消息时自动清空草稿；有草稿的会话在列表中按草稿更新时间参与排序（置顶优先规则不变）。 |
| K6 @提及 | `send_text` 保持不变；新增 `async send_text_with_mentions(conv_id, text, quote_id: Option<String>, mentions: Vec<Mention>)`，`Mention { user_id, start: u32, length: u32 }`（UTF-16 偏移，便于两端文本控件）；`MessageItem.mentions: Vec<Mention>`；`ConversationSummary.unread_mentions: u32`（未读消息中提及我的数量，`mark_read` 清零）；被 @ 的消息即使会话免打扰也作为实时通知（在事件 `MessageAdded` 上新增 `mentions_me: bool`）。 |

## 2. 两端 App

| 编号 | 内容 |
|---|---|
| U1 | 会话列表「删除」调用 `delete_conversation`（二次确认「删除后本机聊天记录将被清除」），去掉 App 自己的隐藏逻辑。 |
| U2 | 长按消息菜单新增「转发」：弹出会话选择（可多选，含最近会话与好友，支持搜索），确认后调用 `forward_message`；转发的消息在气泡顶部显示「转发的消息」小标签。 |
| U3 | 草稿：离开聊天页时 `set_draft`，进入时恢复；会话列表预览显示红色「[草稿]」前缀 + 草稿内容。Android 现有的 App 侧草稿迁移到核心 API。 |
| U4 | @提及：群聊输入 `@` 弹出成员选择（含「所有人」除外，不做 @所有人），插入 `@昵称 ` 并记录区间；发送走 `send_text_with_mentions`；气泡内 @ 片段用强调色；提到我的气泡左侧有强调竖线；会话列表有 `unread_mentions` 时预览前显示红色「[有人@我]」；免打扰群里被 @ 仍弹通知。 |
| U5 | iOS：消息搜索结果点击跳转并高亮该消息（向上翻页直到找到，Android 已实现，行为对齐）。 |
| U6 | 实测回归：P-D「通知对应动态不在第一页」分支需真实验证（发足够多动态使目标不在第一页）。 |

## 3. 验收
- core：`cargo test` 全绿（新增 K1–K6 单元与 e2e 覆盖，含迁移）；导出差异仅限本文件所列新增。
- 两端：构建、单元测试通过；在各自隔离的模拟器/测试服务端上实测 U1–U6 并截图（`docs/screenshots/<platform>/v3-*.png`）。
- 最终由协调者部署到用户正在使用的模拟器，并做 Android↔iOS 互通回归（转发、@提及、草稿）。
