# Hush 管理后台与服务端性能升级

日期：2026-09-30。延续 [设计文档](2026-09-24-hush-design.md)、[接口 v2](2026-09-24-api-v2.md)。

## 0. 隐私边界（不可突破）

聊天内容端到端加密，**管理后台永远看不到、也不提供任何查看聊天内容的入口**。后台只能看到服务端本来就持有的数据：账号资料、好友/群成员关系、朋友圈（明文）、队列与附件的**数量和大小**、连接状态。后台里凡涉及消息的地方只显示计数与字节数。

## 1. 管理后台（A 系列）

### 1.1 形态与安全
| 编号 | 内容 |
|---|---|
| A1 部署 | 与服务端同一个二进制。独立监听地址 `--admin-addr`（默认 `127.0.0.1:8081`，空字符串表示不启用）；页面用 `go:embed` 内嵌的静态文件（原生 HTML/CSS/JS，不引入前端构建工具链与外部 CDN），路径 `/`；接口在 `/admin/api/*`。 |
| A2 管理员账号 | 独立的 `admins` 表（用户名、密码哈希 `bcrypt` 或 `argon2id`、角色、创建时间、最近登录、是否停用）。首个管理员通过子命令创建：`hush-server admin create --data <dir> --username <u>`（密码从标准输入或 `HUSH_ADMIN_PASSWORD` 读取，最少 12 位）。不提供默认账号、默认密码。 |
| A3 会话 | 登录后发随机会话令牌，存 `admin_sessions`（只存哈希），Cookie `HttpOnly; SameSite=Strict`（https 下加 `Secure`），12 小时无操作过期；所有写操作校验 CSRF 令牌（登录响应下发，前端放请求头 `X-CSRF-Token`）；登录限速（同 IP 每分钟 5 次，同用户名连续 10 次失败锁定 15 分钟）。 |
| A4 角色 | `owner`（全部权限，含管理员管理与系统设置）、`moderator`（用户与内容管理，不能改系统设置和管理员）、`viewer`（只读）。 |
| A5 审计日志 | `admin_audit` 表记录每一次写操作：时间、管理员、动作、对象、参数摘要、来源 IP。后台可查询，**不可删除**。 |

### 1.2 功能页面
| 编号 | 页面 | 内容 |
|---|---|---|
| A6 概览 | 仪表盘 | 注册用户数、今日新增、在线连接数、今日活跃（今日有过认证请求的用户数）、群组数、朋友圈动态数、离线队列条数与字节数、附件数量与占用、服务器运行时长与版本；最近 30 天的注册与活跃趋势图（用内嵌 SVG 画，不引第三方库）；最近 24 小时每小时投递消息数。 |
| A7 用户 | 列表（邮箱/昵称/ID 搜索、分页、按注册时间或最近活跃排序）、详情（资料、注册时间、最近活跃、平台与设备名、好友数、所在群、朋友圈条数、队列积压、附件用量）、操作：**停用/启用账号**（停用后令牌失效、无法登录、在线连接被断开，事件 `logged_out{reason:"account_disabled"}`）、**强制下线**（作废令牌）、**删除账号**（级联清理好友关系、群成员、朋友圈、队列、密钥；二次确认需输入邮箱）、重置资料（清空违规昵称/头像/签名）。 |
| A8 群组 | 列表与搜索、详情（成员、角色、创建时间、消息计数）、操作：解散群、移除成员、转让群主。 |
| A9 朋友圈审核 | 动态列表（按时间，可按作者筛选，显示文字与图片缩略图）、删除动态、删除评论；被举报内容优先显示。 |
| A10 举报 | 新增客户端接口 `POST /v1/reports {target_type: user|moment|comment|group, target_id, reason, detail?}`（限速）；后台举报队列：待处理/已处理、处理动作（忽略、删除内容、停用账号）与处理备注。 |
| A11 注册控制 | 注册模式：开放 / 仅邀请码 / 关闭；邀请码管理（生成、次数上限、过期时间、已使用记录、作废）；邮箱域名白名单。`POST /v1/auth/verify` 在仅邀请码模式下对新用户要求 `invite_code`（老用户登录不受影响），错误码 `invite_required` / `invite_invalid`。 |
| A12 系统公告 | 发布公告（标题、正文、可选截止时间），通过服务端事件 `announcement{id,title,body,created_at}` 推送给所有用户（走现有 outbox 队列）；`GET /v1/announcements` 供客户端拉取历史。 |
| A13 系统设置 | 查看并在线修改（写入 `settings` 表，立即生效，owner 专属）：限速参数、队列配额、上传配额、令牌有效期、注册模式。启动参数作为默认值，后台修改覆盖它。 |
| A14 存储与维护 | 附件占用排行、手动触发清理任务、在线备份（SQLite `VACUUM INTO` 到 `data/backups/`，列出与下载备份，保留最近 N 份）。 |
| A15 监控 | 实时指标页（每 5 秒刷新）：在线连接、每秒请求数、各接口 P50/P95/P99 耗时、数据库写队列等待、队列积压、Go 协程数与内存；`/metrics`（Prometheus 文本格式，只在 admin 监听地址上提供）；最近的 5xx 与 panic 记录。 |
| A16 管理员与审计 | 管理员增删改、重置密码、停用；审计日志查询（按管理员、动作、时间筛选）。 |

### 1.3 界面要求
- 左侧导航 + 顶部栏（当前管理员、退出）；表格带分页与搜索；危险操作红色按钮 + 二次确认弹窗；操作结果有提示条；支持浅色/深色；窄屏可用。
- 全中文界面；时间显示本地时区；数字带千分位；字节数自动换算单位。
- 无障碍基本要求：表单有 label，按钮可键盘操作。

## 2. 性能与并发（P 系列）

| 编号 | 内容 | 验收 |
|---|---|---|
| P1 压测工具 | `server/cmd/hush-loadtest`：模拟 N 个用户（注册、上传密钥、建立 WS、互为好友的小圈子、按速率发 Olm 消息与群消息、ack），输出吞吐、投递延迟 P50/P95/P99、错误率。 | 能一条命令跑出报告；结果写入 `server/BENCHMARK.md`。 |
| P2 读写分离 | SQLite 保持单写连接，新增只读连接池（WAL 下并发读，`PRAGMA query_only`），所有只读查询走读池；写路径保持事务语义。 | 读多写少的接口在并发下不再排队；`go test -race` 全绿。 |
| P3 写入批量化 | 队列入队、ack 删除、`last_used_at` 刷新等高频写操作合并成批（组提交），减少事务数。 | 压测下写吞吐提升，有前后对比数字。 |
| P4 投递路径 | WS 写出合并（同一连接短时间内的多帧一次 flush）、大群扇出一次事务完成并避免重复序列化、在线状态查询不加全局锁。 | 大群（200–500 人）发消息的 P95 延迟有前后对比。 |
| P5 资源上限 | 最大连接数与每 IP 连接数上限、请求并发上限（上传单独限流）、优雅停机（停止接新连接 → 等待在途请求 → 关闭 WS → 关库）、`pprof` 只在 admin 地址提供。 | 压测打满时服务不崩溃，返回 429/503；SIGTERM 后数据不丢。 |
| P6 基线目标 | 单机（本机）目标：2,000 条并发 WS 连接下，单聊消息端到端投递 P95 < 200ms、吞吐 ≥ 1,000 条/秒，错误率 < 0.1%。达不到要在报告里说明瓶颈。 | `BENCHMARK.md` 给出改造前后两组数字。 |

## 3. 缺陷修复（F 系列）
以本轮服务端只读审查报告为准：A 类（已复现）全部修复并补回归测试；B 类按严重程度修复；C 类结合 P 系列处理。

## 4. 兼容性
- 对客户端的既有接口保持向后兼容；新增的 `invite_code`、`/v1/reports`、`/v1/announcements`、事件 `announcement` 与 `logged_out{reason:"account_disabled"}` 写入 `server/API_NOTES.md`，客户端适配另行安排。
- 数据库迁移走现有版本框架，在真实库副本上验证后再部署。
