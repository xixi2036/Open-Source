# Hush 接口 v2（审查暂缓项收尾）

日期：2026-09-24。本文件是服务端、核心库、两端 App 在本轮的**共同契约**。所有改动必须向后兼容已存在的数据（本地库与服务端库都通过迁移升级，不清数据）。

## 1. 服务端（server/）

| 编号 | 内容 |
|---|---|
| S-A | `GET /v1/moments/{id}` → `Moment`（可见性规则与 feed 相同：作者本人，或作者好友且在可见范围内；否则 404 `not_found`，不泄露存在性）。点赞/评论过滤规则同 feed。 |
| S-B | `Profile` 新增可选字段 `email`：仅当查看者是本人或与该用户**互为好友**时返回，否则省略（`omitempty`）。适用于 `/v1/me`、`/v1/users/{id}`、`/v1/friends`、好友申请中的 from/to（申请双方可见彼此邮箱：发起方本来就是按邮箱搜索的）、群成员资料不返回邮箱。搜索接口 `/v1/users/search?email=` 维持原样。 |
| S-C | 令牌滑动过期：令牌 90 天未使用即失效（每次使用刷新 `last_used_at`，写库节流为每小时最多一次）。失效后所有接口返回 401 `unauthorized`，WS 握手 401。`--token-ttl` 参数可配置（0 = 永不过期，测试用）。迁移时现有令牌 `last_used_at` 取迁移时刻。 |
| S-D | Outbox：业务写入与其产生的事件在**同一事务**内写入队列（替代"提交后再入队"），崩溃不丢事件；在线推送在提交后触发。 |
| S-E | `moment_media(moment_id, attachment_id)` 关联表，迁移回填；附件清理改用关联表，不再 `json_each` 扫描全部动态。 |
| S-F | Olm 批量发送的关系校验改为一次集合查询。 |
| 不做 | JSON DTO 从 store 迁到 api 层（纯搬迁、收益低，保持现状）。 |

## 2. 核心库（core/）——UniFFI 导出变更（两端需同步适配）

| 编号 | 变更 | 类型 |
|---|---|---|
| C-A | `MessageItem` 新增 `sort_ts: i64`（与 `messages(before_ts)` 游标同一口径）。 | 新增字段 |
| C-B | `MessageBody::CallLog` 新增 `reason: CallEndReason`；`enum CallEndReason { Completed, Missed, Rejected, Busy, Cancelled, Failed }`。旧库中已有记录迁移为：duration>0 → Completed，missed → Missed，其余 → Cancelled。 | 新增字段+新枚举 |
| C-C | `Profile` 新增 `email: Option<String>`（来自 S-B）。 | 新增字段 |
| C-D | `async fn moment(id: String) -> Result<Moment>`（S-A；404 → `HushError::NotFound`）。 | 新增方法 |
| C-E | `HushError` 新增变体 `KeyMismatch { message }`：`HushClient::new` 在 db_key 与已有库不符时返回它（替代 Storage + 文案匹配）。 | 新增变体 |
| C-F | `CoreEvent::MessageAdded` 新增字段 `backlog: bool`：该消息来自连接建立后、`queue_empty` 之前推送的积压（或 HTTP 补拉），平台据此不弹实时横幅。 | 新增字段 |
| C-G | 任何接口或 WS 握手收到 401：清除本地登录态（与 4001 相同处理），发 `LoggedOut { reason: "session_expired" }`。 | 行为 |
| C-H | Inbox：收到的信封先落库（inbox 表，原始密文）再解密处理，处理成功后删除；进程在解密后、落库前被杀不再导致重投的消息无法解密（重启后从 inbox 继续处理，已推进的棘轮状态与明文在同一事务保存）。 | 内部 |
| C-I | 附件流式加密格式 v2：分块 AES-256-GCM（64 KiB 明文块，nonce = 8 字节随机前缀 ‖ 4 字节块序号，最后一块在 AAD 中标记 final），文件→文件流式加解密，内存占用与附件大小无关；`digest` 仍为整个密文文件的 SHA-256。解密兼容旧格式 v1（附件元数据增加 `format` 字段，缺省为 1）。 | 内部（Content 附件项新增 `format`） |

## 3. 两端 App

| 编号 | 内容 |
|---|---|
| P-A | 分页改用 `sort_ts`（删除自行推算的逻辑）。 |
| P-B | 通话记录按 `reason` 显示：已接通「语音通话 3:21」，Missed「未接来电」，Rejected「已拒绝」，Busy「对方忙线」，Cancelled「已取消」，Failed「通话失败」。 |
| P-C | 单聊设置页显示对方邮箱（有则显示）。 |
| P-D | 朋友圈通知点击 → 打开单条动态详情页（`moment(id)`）；动态已删除/不可见时提示「该动态已不可见」。 |
| P-E | 数据库密钥不匹配用 `KeyMismatch` 判断（删除文案匹配）。 |
| P-F | 实时横幅只对 `backlog == false` 的消息弹出（iOS 删除基于时钟的判断）。 |
| P-G | 收到 `LoggedOut(session_expired)` 时回到登录页并提示「登录已过期，请重新登录」。 |
| Android | A15：数据库在后台线程打开，启动显示启动页，打开完成前各组件等待；A25：release 构建启用 R8（UniFFI/JNA/WebRTC keep 规则）与独立签名配置（本地 keystore 不入库，缺省回退 debug 签名），在独立模拟器验证 release 包可安装运行。 |
| iOS | IOS-21：把 HushCore 拆出 `ConversationStore`、`ContactsStore`、`MomentsStore`，视图不再直接调用 `core.client`；IOS-24：`SWIFT_STRICT_CONCURRENCY=targeted`（SDK 自身警告不阻塞），修掉项目代码的并发警告。 |
